## 0.8.0 — 2026-09-07

### Infrastructure: Verification Contracts for the Agent Pipeline

**Background:** Escape-rate data from two repos told the same story — this repo's last measured window put 57% of tagged fixes at post-merge discovery, and the sibling npvitals retrospective (2026-09-07, six same-day escapes) traced its failures to two mechanisms: tests that verified a call was *invoked* rather than that it had the intended *effect*, and completeness claims ("all N routes are gated") written in confident prose and never diffed against their own source of truth. The pipeline's gates existed but graded write-ups instead of evidence. This release makes evidence the thing that flows between phases, and mechanizes the parts that must always happen.

**Changes:**

- **Evidence classes (E1/E2/E3).** Every load-bearing claim in a phase output is tagged: E1 (command ran, literal output pasted), E2 (derived from a primary source, enumeration command cited), or E3 (reasoned/unverified — legal, but labeled). An unlabeled quantified claim is E3 by definition. Defined in `CLAUDE.md` → Evidence Classes and Entry Checks.
- **Claims ledgers + entry checks.** Each phase's work-log section ends with a 3–7-row Claims Ledger; the next phase opens by re-deriving those claims *before reading the claimed answers* (derive-then-diff, never read-then-confirm). Load-bearing diffs trigger the standard loop-back; non-load-bearing ones are logged in a Prior-Phase Spot-Check section. Template: `docs/work-log/_template.md`.
- **Verification Contract sections in all nine agent files** — each states its phase's entry-check target, exit-ledger contents, and self-check emphasis, replacing overlapping prose (net +89 lines across the roster).
- **Work-log gate hook** (`scripts/worklog-gate.mjs`, harvested from the npvitals fork and re-proven here with 48 unit tests) — the first Edit/Write-blocking PreToolUse hook: edits under `src/` or `drizzle/` require a work-log that names the file or is same-day-fresh, and a substantive Phase 4 section must carry a "What was NOT verified" heading. Fails open on any parse error. Trivial-class edits get a local, operator-invoked, single-use `/trivial` exemption (DECISION-032) — agents may not self-issue it.
- **Two new tripwires**, both wired into `npm run check` and `/pre-push`: `check:ledger` (every post-cutoff work-log with a Complete phase ≥ 3 must carry a Claims Ledger; grandfather cutoff 2026-09-07 per DECISION-033) and `check:agent-symbols` (no agent file may reference a retired script or symbol).
- **Cross-model judgment gates.** Phase 5 (qa) and the Phase 6 analyst invocation are spawned with a model override distinct from the Phase 4 implementer — cheap insurance against same-model self-preference, per the NeurIPS 2024 self-recognition findings cited in `docs/verification-contracts-design.md`.
- **Proven-by-failing discipline.** Every gate above was revert-proven on the day it shipped: each was made to fail (planted symbol, ledger-less fixture, uncovered edit payload) and seen failing before its green run counted. A quantifier-linter increment measured a ~5% true-positive rate against the real work-log corpus — under its own pre-registered kill criterion — and was deleted rather than shipped noisy.

**Known residual** (tracked in `docs/TODO.md`): the hook has been exercised through its exact CLI/stdin contract but has never fired inside a live harness session — the operator live-fire check is the top Next Up item.
